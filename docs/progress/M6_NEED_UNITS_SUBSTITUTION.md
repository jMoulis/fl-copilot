## M6-T07 — Conservative deterministic score calculation

The runtime-neutral scoring engine replays the complete current evidence set rather than applying an increment to the previous learned score. Corrections replace their earlier revision; missing/invalidated evidence removes its contribution. Duplicate IDs, shared observed days/sales, reused incident IDs and observation/reference overlap never count as independent confirmations. Equal-version divergent revisions and foreign edge/store identities are refused. Pending and neutral evidence cannot weaken a relationship. Rejected/unconfirmed/proposed relationships are not eligible and the engine never changes their human decision.

Policy `substitution-score.v1` is explicit and configurable: business weights need=.3, usage=.3, price=.1, packaging=.1, observed=.2; weights total 1. Unknown optional components are omitted and weights renormalized; explicit zero remains zero. Observed strength starts at a neutral .5, separate from human compatibility. Each independent informative record contributes at most .05 × evidenceStrength × dataQuality, halved for known confounders/partial days. With the current evidence strength ceiling .5, one observation moves the observed component by at most .025. The engine does not convert arbitrary percentage uplift into a substitution probability.

Confidence is capped at .5 while v1 context remains incomplete. It depends on accumulated information and agreement: ceiling × (1 − exp(−information)) × abs(support − contradiction)/information. Repeated consistent independent evidence increases it gradually; reliable contradictory evidence reduces observed strength and agreement. The daily evidence engine still emits NEUTRAL for decreases under incomplete context, so these decreases cannot masquerade as reliable contradictions. Neither wall-clock passage nor repeated synchronization increases confidence. Original event closure determines lastEvidenceAt, not job execution time. Every result carries the versioned policy and evidence ID/version/inputRevision/reason decisions for the next audit increment.

This increment completes the shared calculation and acceptance tests. It deliberately does not publish learned values into canonical relationships yet: M6-T08 will atomically persist the score update with immutable evidence-linked history and synchronization. Without that audit integration, calling the calculator is side-effect-free and production relationship metrics remain unchanged. No migration, AI request, native dependency or EAS build is needed. Paid EAS builds are reserved for substantial physical-device acceptance requiring the owner's feedback.

Verification: 562 local tests pass, including nine new score acceptance scenarios. Repository structure, lint, strict TypeScript, formatting, API compilation and the built-handler runtime import check pass. No database persistence path changes in this increment; the existing Atlas transaction tests remain CI gates. No EAS build is launched.
