# M0 foundation implementation and acceptance

Date: 2026-09-25.

## Scope and source specifications

This increment implements the code for M0-T01 through M0-T08 from `docs/specs/IMPLEMENTATION_PLAN.md`. It follows the native architecture, primary navigation and error DTO from the canonical architecture, UX and database/API specifications. No source specification was replaced.

M0-T01 had directories but no runnable typecheck/test/lint toolchain; that gap is now filled. This is an early foundation increment, not completion of M0 or of the MVP.

## Implemented

- Root pnpm lockfile, Node version, Turborepo, strict package typechecks, ESLint, Prettier and GitHub Actions checks.
- Expo SDK 57, React Native 0.86, Expo Router, NativeWind v4, form dependencies, scoped UI-only Zustand store and remote-coordination QueryClient.
- Five French tabs with honest empty states, plus a working About modal.
- AppScreen, AppHeader, MetricCard, SectionCard, StatusBadge, PrimaryButton, SecondaryButton, InlineAlert, EmptyState, SyncState and BottomSheet.
- Fastify app/server separation, Zod request/response validation, environment validation, public process liveness, generated correlation IDs, sanitized French errors and graceful shutdown.
- Native MongoDB driver with a shared pool, retryable readiness, validated settings, ordered migrations and the `schemaMigrations` registry.
- Native Expo SQLite initialization before application rendering, typed Drizzle tables and ordered transactional local migrations.
- Initial local tables for application metadata, inbox state, outbox commands, conflicts, background jobs and local file metadata, with the specified pending-work indexes.
- Stable device identity generated by Expo Crypto, persisted in local metadata and exposed with the initialized database context.
- Native email-code authentication, one-time challenges, rotating refresh tokens, remote session revocation, SecureStore persistence and offline session markers.
- Shared `ApiErrorDto` and health schemas in `packages/sync-contracts` (no premature sync protocol implementation).
- Browser preview using the same Expo components, with `pnpm preview:web`; it does not replace native platform acceptance.
- A Maestro navigation flow for later repeatable native E2E execution.

The first remote infrastructure migration initializes the migration registry and its unique name index. The second adds authentication indexes for users, challenges, device sessions and store memberships. No source capture, imports, business KPI, synchronization or recommendation is represented as working.

The API tests cover connected and degraded readiness, independent request IDs, 404 errors, valid/invalid Zod payloads, malformed JSON, oversized payloads, safe internal errors, response schema failures, environment validation and authentication routes. The conditional integration suite covers MongoDB migrations, one-time-code consumption, refresh-token rotation and reuse revocation. The local SQLite tests cover schema creation, restart persistence, atomic rollback without losing pending outbox work and stable/distinct device identity. Business authorization/store-isolation tests belong with future business endpoints; `/health` is intentionally public and store-independent.

The Maestro scenario is committed but has not been executed: Maestro is not installed. The iOS checks above were performed directly through the simulator UI. VoiceOver, TalkBack, maximum text sizes and physical-device testing remain open; component implementation alone does not close those gates.

## Local toolchain findings

- The login shell resolves Node 24.14.0 through NVM and pnpm 9.15.9.
- Homebrew runs natively on Apple Silicon from `/opt/homebrew`; CocoaPods 1.17.0, Ruby and pkgconf are ARM64.
- Xcode 27 is installed. Expo SDK 57.0.25 uses the official `expo-build-properties` scene-life-cycle option required when building SDK 57 with the iOS 27 SDK.
- Expo prebuild and `pod install` complete without custom patches. Native iOS and Android debug builds pass.
- The optional experimental typed-route setup stalled Metro locally. It is disabled in the app configuration; TypeScript strict checking remains enabled.
- The native validation server used port 8088 with TypeScript auto-setup skipped; the compiled web preview uses port 8087.
- The project-local commands use EAS CLI 24.8.0 through `pnpm dlx` after `nvm use`; this avoids the obsolete Intel CLI installed under `/usr/local`.
