# Commercial documents — progressive list and bounded reads

## Scope

V1 UX L5 / M7 documents and M8 performance. The document screen keeps the canonical PDF capture, immutable originals, existing upload recovery, review summaries, source opener and preparation paths. No model instruction, provider, business command, migration or publication rule changes.

The import action is compact. Search matches filenames and registration dates (French/ISO, case/accent insensitive). Filters distinguish waiting documents, received analysis results and stages to check; confirmed uploads do not become failures because of a stale upload-job error. A received page is not a claim that the entire analysis is finished. Sources known only through synchronized review pages remain in the same searchable list with their original/synthesis actions. Ten document cards are mounted per page, with accessible previous/next controls and a return to the list heading when paging. Current search/filter/page survive detail navigation and focused refresh within the retained route; this increment does not claim restart persistence for these presentation choices. An explicit import resets restrictive filters and reveals the canonical captured/duplicate source by ID, including homonymous older PDFs. A newer sync read can fulfill this pending focus; later manual search/filter/paging cancels it.

Preparation/context readers mount only on first expansion, then remain mounted when folded to retain their state. Existing local state survives a read failure, with an explicit local refresh action. Late reads after blur/new focus are ignored. First entry reads SQLite even during synchronization; intermediate progress is coalesced and settlement/pull revisits local state. There is no screen-specific timer or new network request.

Upload-state reads change from **200 SQL requests to 1**. The complete **list snapshot reader** (documents/jobs/review pages/decisions) makes four requests; visible original/recovery panels can add their own reads, so this is not a claim of four total requests for the whole screen. Earliest-job semantics remain identical.
