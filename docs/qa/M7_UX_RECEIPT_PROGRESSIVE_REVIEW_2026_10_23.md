# Progressive waste receipt review

## User-visible behavior

Previously every `TO_REVIEW` group opened all its occurrence editors automatically. Publication issues forced groups open and disabled the fold button; a long ticket could mount many inputs and alias readers at once. Review is now explicit and progressive: compact stored-value previews remain visible, with review/error/unsaved indicators, and a single stable source-line UUID selects the active editor across the receipt. Repeated labels have previous/next occurrence controls and a source-line number. No quantities, amounts or identities are aggregated by this presentation grouping.

Folding or choosing another occurrence preserves the existing screen-owned drafts, including deliberate blanks and known zero. Unsaved and stale-version checks, exit confirmation and canonical publication validation remain active. Only the existing explicit save writes a line; folding, selection and issue navigation do not write or publish. Save-in-progress disables review navigation. After a successful save the corresponding active editor closes; an older asynchronous callback cannot close a different subsequently selected editor.

The correction summary shows five entries initially and an explicit control for the rest. Clicking an issue opens its exact occurrence, including repeated labels. When opening another group changes heights, navigation discards that group's old coordinate and waits for the new native layout before scrolling. Existing same-group and header navigation remain immediate. Compact piece quantities no longer carry an irrelevant missing-weight label; unavailable values and zero remain distinct.

## Verification and boundaries

- Four mounted tests use the **actual receipt route, line fields, grouping, draft helpers and issue components**, with isolated repositories/auth/navigation. A fixture with 140 lines needing review mounts no line editor or alias reader initially; 100 explicit changes leave exactly one actual form, and folding leaves none. Alias reads occur for the 101 deliberately visited forms, rather than all hidden lines.
- The same route tests retain an explicit blank and zero across folding, occurrence changes and a changed source label/version. A stale save remains disabled; publication with a hidden unsaved draft invokes validation and never publishes. Explicit save locks navigation/fields, writes once and clears only its saved draft. A 140-entry correction report initially exposes five controls, reveals the rest on request and opens occurrence 2 / source line 140 for a repeated label. These are UI/scheduling tests with repository doubles, **not** 100 physical writes, network synchronization or native latency measurements. Existing migrated SQLite receipt, publication, conflict and editor-state suites remain the business persistence evidence.
- Two hook tests verify fresh rather than stale expanded-group coordinates, coalesced layout events, immediate same-group/header navigation and cancellation of an outstanding animation frame on unmount. There is no new polling loop or business coordinator.
- Production review-group, compact-preview and issue-summary components were compiled and inspected locally at 390×844 and 320×740 with explicitly labelled presentation fixtures and no API/auth/database writer. At 320, document width equalled viewport width and occurrence buttons stacked at 246×50 points. The issue control selected the exact second source occurrence; browser error logs were empty. The local visual fixture used a labelled editor slot, not the production form: actual form behavior is the separate mounted-route evidence above. This does not claim native keyboard, VoiceOver/TalkBack or physical save acceptance.
- Screenshots were inspected in the conversation; no saved image/video is claimed. The temporary QA route is archived outside Git under `artifacts/receipt-review-2026-10-23`, removed before final checks, and the owned Metro process stopped. Its automatic tsconfig rewrite was reverted. The optional DevTools installation warning did not prevent rendering; no toolchain change was made.
- React review: one presentation component replaces eager editor mounting; drafts remain in the existing receipt owner, selection uses stable source UUIDs, errors remain visible while folded, and asynchronous save close uses the current selected UUID. No migration, new native dependency, provider/model call, remote writer or change to immutable sources, Outbox, quantities, matching or publication rules.
