# M7 — store physical layout persistence

Scope: PR 266, workstream 6, the first two delivery blocks of `STORE_LAYOUT_SPEC.md`. This is repository and synchronization groundwork; no native editor or new Copilot mutation is exposed yet.

## Automated evidence

- Shared model: two islands × eight single-face elements, individual bac and upper shelf, three TGs, no invented mobile; qualified reference measurements and unknown values; unique IDs, face slots, surface ownership and mobile host integrity. Group envelopes are separate from elementary furniture; neither is a feasibility verdict.
- SQLite: additive v48 → v49 upgrade preserves queued work and seeds nothing. Head, immutable snapshot, operation replay and Outbox commit together. A failed commit leaves none of them. Restart/replay preserves the newer draft and the original stable furniture IDs.
- Actions: save incomplete drafts, adopt only the exact current draft, discard without deleting its snapshot, restore into a new version. Historical pages use version plus ID so competing snapshots of the same version are not skipped.
- Synchronization: sequential revisions drain in order; old acknowledgements/pulls preserve newer dirty drafts. Scoped and immutable history rejects a changed snapshot or foreign store. Capability adoption reboots the snapshot without losing dirty edits; unsupported clients do not receive these entity types.
- Conflict: both local and remote intentions survive. Choosing local explicitly creates a new draft based on the latest compared remote revision. Choosing remote retires queued writes and retains rejected local history. A changed comparison or an in-flight write prevents resolution; there is no automatic merge.
- HTTP: authenticated MANAGER identity is forwarded to the writer; a viewer cannot write. Mongo verifies the actor, tenant, version, exact reviewed content and restoration source. Idempotent retries do not duplicate history or business observations.
- Transactional Mongo: disposable database; draft/adopt/discard/restore, replay, isolation, legacy negotiation, simultaneous edits and complete two-device SQLite → Outbox → Mongo → pull cycle. The losing intention remains on its originating device, separate from the canonical accepted history.

Local run: 2,007 tests passed; 483 environment-dependent tests skipped locally, including six layout Mongo cases run separately against the disposable database. All six transactional layout cases passed.

Commands: `pnpm check`, `pnpm format:check`; `TEST_MONGODB_URI=… TEST_MONGODB_TRANSACTIONS=true pnpm exec vitest run apps/api/test/store-layout.integration.test.ts` with a disposable database name generated by the test. Never print the URI or use the production database for fixtures. CI also runs transactional tests and exports.
