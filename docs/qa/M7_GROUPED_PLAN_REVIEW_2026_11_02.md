# Grouped commercial plan review — 2 November 2026

## Outcome and boundaries

One explicit manager confirmation can validate the selected pending offer versions and save the existing week's TG plan. The mandatory standalone commercial-offer validation view is removed, not hidden as another prerequisite. The existing week recap and private chat plan card use the same canonical offer/plan writers and local transaction; no new business model, collection, migration, tool or provider call. Essential terms remain visible; chat source/product/operation detail is disclosed on demand. Preview content cannot navigate to reminders for an unsaved operation.

This increment starts from a saved draft and retained commercial choices. It does not yet collapse choice/draft creation into the final decision, allow an offer-free canonical strategy plan, remove the document-processing pipeline, ingest a book corpus or prove strategic advice quality. Qualitative advice still needs none of those validations. Existing targeted offer editing/validation, history, immutable originals, restart/correction and execution services remain available.

## Integrity and compatibility

- Opening/receiving a review creates no approval or plan. Prospective validation objects are memory-only deterministic construction inputs; the public review basis lists pending IDs/versions, source digest and store-settings revision. Their prospective state is not an approval claim.
- Current product identities/versions, units, retained choices, draft, source metadata/extracted review fields, PDF preference and current plan revision are checked before confirmation. Store settings are re-read; unknown capacity is not zero. Planned TG assignments exceeding declared active produce TG capacity need correction; unused historical draft capacity alone does not block adoption. No semantic TG label is mapped to a physical surface UUID.
- Offer validations, plan, histories and ordered Outbox commands commit together, before asynchronous sync. Private chat confirmation/result join the same transaction. Cancellation, save failure or stale references leave no partial approvals/plan. Existing approved versions are reused. Duplicate taps/private retries do not duplicate the plan or declare execution.
- Capability `x-copilot-plan-validation: 2` negotiates grouped server previews. Version 1 still requires prior validations and gets no new review field. Earlier private cards without the optional review basis remain supported. The API must release before the new native client; keep PR404's settings compatibility after any context writes.
- Grouped model output is a short summary/status/evidence; the complete proposed plan remains in the owned native card. Existing 13,000-byte preview/16,000-character message bounds remain. Oversized plans fall back to the week screen, without silent truncation or approval.
