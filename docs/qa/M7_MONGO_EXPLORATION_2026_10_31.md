# Scoped Mongo exploration — 31 October 2026

## Authorized scope

The owner approved model-authored list/get/aggregate reads to avoid one custom tool per analytical question. This increment uses one read-only adapter over three existing canonical collections: products, productDailyPerformance and departmentDailyPerformance. It creates no database model, collection, index, migration, native capability, credentials or operational writer. Existing provider/model/budgets are reused, no live paid AI call. The functional spec records this explicit narrow override of its old no-generated-query wording.

`mongo_list` discovers the views, field dictionary and allowed syntax or reads stable id pages. `mongo_get` reads one known record. `mongo_aggregate` accepts an ordinary JSON Mongo pipeline string (bounded provider schema), up to twelve stages: match/project/set/group/sort/limit/skip/count, with a small expression/operator allowlist. Model stages only see a safe projection; storeId, raw snapshots, private notes/accounts/chats, code, arbitrary collections, user joins and writes cannot be reached. The only product join is server-owned and separately scoped to the store. Daily reads require an explicit period; ids are not invented/rewritten.

## Numeric and operational safeguards

Canonical decimal strings become Mongo Decimal128 and serialize exactly as strings. Status-gated missing/malformed inputs stay null; every user sum tracks numeric inputs so an all-null sum remains null. Quantity aggregation must select one explicit unit at the first match or retain quantityUnit in a single group; altering/removing units or collapsing a second group is refused. Pending unit recomputation and unknown units mask quantities. Known versus estimated purchase-cost waste remain separate. Logical deletion is exposed separately from ACTIVE status, so active-catalogue queries can exclude tombstones while historical figures remain readable. Current catalogue labels/category/nature are not historical classification; HT/TTC is still unconfirmed.

The source scan is bounded at 10,000 products / 100,000 daily rows, 3 seconds, no disk spill. Exceeding the prefix returns no sampled totals. Output is twenty rows maximum (stable cursor for list), size/depth bounded. Coverage counts describe projected source input BEFORE model filters, not complete per-group calendar coverage. No raw import/publication double counting. Large technical input revisions (over 20 KB in a read-only real sample) stay in their canonical audit and are not exported to the model; only the calculation timestamp is exposed. `$avg` and arbitrary ratios are exploratory, not a certification of business formulas; the existing analytics_period/analytics_query remain for official comparisons, paired quantity/prices, Pareto and coverage. General unit conversion, lookup/window/facet/unwind, raw source rows and unrestricted Mongo/JS are not part of this first increment.

The Mongo-enabled model catalogue removes analytics_daily and analytics_product_changes. Legacy/internal readers stay for compatibility and old fact replay. This adds three generic tools while retiring two overlapping ones; it does not claim every specialized tool has already been removed. Native discovery/progress/evidence/streaming are reused. Read count, timeout, token/input and evidence ceilings are retained; steps permit discovery, bounded reads and a final answer. Every result is bound to its normalized request, with evidence and query digest. The existing private fact trace can replay these reads, including changed projections; no new provenance collection or false unchanged status is introduced.
