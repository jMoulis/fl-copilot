## Change

- **Imports**: single/multiple XLSX selection and ZIP selection, then recent archives/batches identified by filename and actual import timestamp. Searching names/dates and older pages remains local. The same archive and its batch are not duplicated among the loaded history. Upload recovery is a separate lazy sheet.
- **Batch**: a page sheet owns the files, search, filters, incremental pages and publication labels derived from committed source records. Extra batch actions are collapsed; extraction failures/ignored-file counts remain available there, and older archives retain their import timestamp even when their batch header is outside the loaded history page. Every retained file status has an open action. The file sheet is presented inside the batch sheet, preserving its mounted scroll surface. Closing refreshes only the reviewed item and committed publication labels, retaining previously loaded pages/search/filter; it does not automatically publish a corrected overlapping file.
- **File**: the header uses the basename, retaining a relative-path subtitle when applicable. Summary, product review and comparison are distinct sections. Overlap opens comparison first. Ambiguous rows appear first, with a reason and a direct route to the relevant product resolution; general local catalogue search reuses the existing picker and conflict controls. Product review and comparisons have search and bounded 20-row pages instead of a cutoff/show-everything dump. File paging returns to the top, while the parent batch position remains retained.
- **Comparison**: quantity, sales, purchase, margin, RCE, VAT and margin-rate source values are visible, with French formatting and explicit missing values. Multiple incoming/existing rows are not represented as an invented aggregate or a definitive comparison of the first row. Actual duplicate-line reasons remain blockers; a source correction or a safe reconciliation is still required. Parser issues are disclosed. Applying a new version still requires a safe, current fingerprint and an explicit action.
- **Partial publication**: existing continuation/resume methods preserve published matches and source-row IDs, then add only newly resolved WARNING rows. The screen does not copy a new original or replace previously published observations for this flow. Completed duplicates stay read-only, and superseded/conflicted/changed/overlapping continuation errors have French explanations. Partial duplicates remain in the review filter. No business formula, shared contract, migration, server endpoint, AI prompt or publication authorization is added.
- The shared header adds `minWidth: 0` so long filenames can wrap within a narrow native/web flex row rather than overflowing.
